## v9.8 (51) — 把 Markdown 渲染器推倒重写

**问题**：AI 长回答会在某个公式处突然消失，但复制出来的原文是完整的（8258 字节，方括号成对，结尾还有引用列表）。也就是说：数据没丢，是渲染器把后半段吞了。

**定位**：旧 Markdown 解析器为了支持多行 `$$` 公式，会一直向下收集到闭合符。模型输出的是 `[...]` 方括号 LaTeX、或者 `x=0\]` 这种不规整闭合，解析器找不到闭合，就把后面整段正文当成公式内容。

**第一版修法（失败）**：全局把 `[...]` 替换成 `$...$`。结果相邻 `$` 互相干扰，又出现新的截断。教训：**不做全局字符串替换**。

**最终方案**：新写 `SafeMarkdown.kt`，逐行渲染：

- 每一行独立判断：代码围栏 / 单行公式 / 标题 / 列表 / 正文 / 空行
- 唯一跨行分支（多行 `$$`）必须找到闭合**且中间没有空行**，否则按原文显示
- 公式识别失败也只显示原文，绝不跳过
- 行内 `$...$`、`\(...\)`、`[ ... ]` 抽出来转 Unicode 混排

**结果**：零丢字成为结构性保证，不靠兜底。

## v9.0–v9.2 (43–45) — 思考内容跟随、停止键、输出上限

- 自动跟随原来只监听正文长度，忽略 `reasoning` 长度 → 展开思考后页面不动
- 停止键原来只 `cancel()` 协程，但流式 `readLine()` 阻塞，要等下一个分片才退出 → 感觉延迟几秒
- 修法：`AiClient` 保存当前连接，停止时直接 `disconnect()` socket；跟随改为监听正文 + 思考 + 展开脉冲
- 输出上限：DeepSeek 非思考 8K → 32K → 64K，思考 64K → 128K

## v8.7–v9.5 (40–48) — 数学公式、复制、滚动

- `SelectionContainer` 实现长按选词 + 每条消息「复制」按钮（真机验证：复制/全选浮层正常）
- `canScrollForward` 判断替代"最后一项是否完整可见"，↓ 按钮不再只在键盘弹出时出现
- 公式渲染：`\frac`、`\sqrt`、上下标、希腊字母、矩阵、cases、`\sum` 上下限堆叠
- 行内公式改为 Unicode 混排，不再单独占一行
- 黑块问题：公式容器深色底 + 空解析结果 → 改成浅底、空内容不渲染、失败回退原文

## v8.0–v8.6 (33–39) — AI 导师与全屏聊天

- 11 家厂商（10 预置 + 自定义），三种协议：OpenAI 兼容 / Anthropic / Gemini
- 流式 SSE、思考内容折叠展示、DeepSeek 官方搜索 API
- 模型查询返回上下文与输出上限（Claude capability 字段、Gemini tokenLimit）
- AI 页全屏：去掉 App 标题与搜索按钮，输入框自适应 1–6 行
